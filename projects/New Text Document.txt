## Phase 5 — Local Malware Sample Management
## Objective

### Allow the researcher to provide a local directory containing malware samples.

## Example:
```
malconfig scan \
    --rule stealc.yar \
    --samples ./samples

```

### Tasks
 - Directory enumeration.
 - Recursive scanning.
 - File identification.
 - Hash calculation.
 - Duplicate detection.
 - File error handling.
 - Integration with YARA engine.
 - Scan statistics.
### Deliverable

### Local malware scanning functionality

## Phase 6 — Match & Artifact Extraction
## Objective

### Convert YARA matches into useful artifacts that can be processed by configuration extractors.

### Supported Artifact Types
 - IP addresses.
 - Domains.
 - URLs.
 - Ports.
 - File paths.
 - Registry paths.
 - Encoded data.
 - Encrypted blobs.
 - Binary structures.
 - Raw data at specific offsets.
### Processing Pipeline
```
YARA Match
     │
     ▼
Identifier
     │
     ▼
Offset
     │
     ▼
Matched Bytes
     │
     ▼
Artifact Identification
     │
     ▼
Extracted Artifact
```
### Deliverable

### Generic artifact extraction framework

## Phase 7 — Malware Configuration Extraction Framework
## Objective

###Create an extensible framework for extracting configurations from different malware families.

### The framework should allow each malware family to have its own extractor.

### Example Structure
```
extractors/
│
├── base.py
├── generic.py
├── stealc.py
├── lumma.py
├── async_rat.py
└── example_family.py
```

### Extractor Pipeline
```
Matched Sample
      │
      ▼
Identify Malware Family
      │
      ▼
Select Extractor
      │
      ▼
Locate Configuration
      │
      ▼
Extract Data
      │
      ▼
Decode / Decrypt
      │
      ▼
Parse Configuration
      │
      ▼
Structured Output
```
### Deliverable

### Extensible malware configuration extraction framework

## Phase 8 — Remote Malware Repository
## Objective

### Allow the tool to scan malware samples stored on a dedicated remote server.

### Architecture
```
┌───────────────┐
│ Malware Tool  │
│    Client     │
└───────┬───────┘
        │
       HTTPS
        │
        ▼
┌───────────────────┐
│ Malware Repository│
│      Server       │
└─────────┬─────────┘
          │
          ├── Sample Metadata
          ├── SHA256
          ├── Sample Storage
          └── Download API
```

### Example API
- GET /api/samples
- GET /api/samples/{sha256}
- GET /api/samples/{sha256}/download
### Tasks
 - Design repository API.
 - Implement authentication.
 - Implement sample metadata.
 - Implement sample retrieval.
 - Implement client-server communication.
 - Implement secure transport.
 - Implement access controls.
 - Implement logging.

### Deliverable

### Remote malware repository and API

### The repository should be treated as malware storage only. Samples should not be automatically executed by the repository server.
