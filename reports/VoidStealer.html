MALWARE ANALYSIS INFOSTEALER WINDOWS MaaS ACTIVE

VoidStealer: Analysis of a MaaS Infostealer with Steam-Based C2 and ABE Bypass

📅 2025 — Present ⏱ 15 MIN READ ✍ SalahEldin Kamil CRITICAL
VoidStealer is a Malware-as-a-Service (MaaS) infostealer first marketed on darkweb forums in mid-December 2025 and actively developed since. The sample is a Windows binary performing host fingerprinting, WMI-based reconnaissance, exception-driven anti-debugging, Steam Community-based C2 resolution, and Application-Bound Encryption (ABE) bypass for Chrome and Edge credential extraction. Strings are obfuscated using per-key Base64 + RC4 decryption.

1. Overview

VoidStealer is a Windows-based infostealer sold as a MaaS offering. The analyzed sample performs a wide range of malicious activities organised into several distinct functional stages:

STAGE 1
Initialisation
Mutex creation, single-instance enforcement
STAGE 2
Fingerprinting
WMI queries for CPU, GPU, OS, memory, locale, wallpaper MD5
STAGE 3
Anti-Debug
Exception-based context manipulation, IsDebuggerPresent
STAGE 4
C2 Resolution
Steam Community profile used as a C2 pointer
STAGE 5
Data Theft
Browser ABE bypass, cookies, credentials, Steam, Discord, Telegram
STAGE 6
Exfiltration
Multipart HTTP upload to resolved C2 endpoint

2. Stage 1 — Initialisation & Mutex

The malware begins execution by creating a named mutex to ensure only a single instance runs at any time. If the mutex already exists, the process terminates immediately.

Mutex Name (decrypted): Global\composerctx
This is a hard IOC — presence of this mutex name on a host confirms an active VoidStealer infection. Hunt for it using ETW or Sysmon kernel object enumeration.

3. Stage 2 — Host Fingerprinting via WMI

After initialisation, VoidStealer gathers detailed information about the victim's system. It abuses COM objects to interface directly with WMI rather than using higher-level Win32 APIs, making detection by API-level hooking harder.

4. Stage 3 — Anti-Debugging

VoidStealer implements a layered anti-debugging mechanism combining exception-based control-flow manipulation with a standard debugger presence check.

①
RtlCaptureContext — captures the full CPU register state (CONTEXT structure) of the current execution point.
②
RtlLookupFunctionEntry — walks the runtime function table to find the RUNTIME_FUNCTION entry for the current instruction pointer, used to reconstruct the call stack.
③
RtlVirtualUnwind — performs virtual stack unwinding to reconstruct the call chain frame by frame.
④
Exception context modification — the captured CONTEXT is altered before being dispatched, redirecting execution to a different code path than a debugger would see.
⑤
IsDebuggerPresent — checks the PEB's BeingDebugged flag. The result alters subsequent execution: if a debugger is detected, the malware takes a decoy or silent path.
Analysis note: The exception-based technique is significantly harder to bypass than a simple PEB check. Standard debugger plugins that patch BeingDebugged=0 will not neutralise the RtlVirtualUnwind-based path. Patch the conditional branch following the context manipulation or use a kernel debugger.
Figure 4 — Exception-based anti-debugging: RtlCaptureContext / RtlVirtualUnwind flow with IsDebuggerPresent check

5. Stage 4 — Steam-Based C2 Resolution

VoidStealer uses an unconventional C2 resolution mechanism that leverages the Steam Community platform as an indirection layer. The actual C2 server address is never hardcoded directly — instead, the malware resolves it dynamically from a Steam profile at runtime.

① Decrypt strings
Base64+RC4
② Build Steam URL
steamcommunity.com
③ WinHttpConnect
60s timeouts
④ GET profile page
/profiles/<steamid>
⑤ Parse persona name
actual_persona_name
⑥ C2 = username
callpit.icu

The hardcoded Steam ID 76561199691513242 is decrypted at runtime and used to construct the profile URL. The malware then parses the HTML response, extracting the value from the <span class="actual_persona_name"> tag. This extracted string is the actual C2 domain, which was observed as callpit.icu.

C2 resilience: This technique allows the operator to update the C2 address without recompiling the malware — simply by changing the Steam account's display name. Blocking steamcommunity.com at the perimeter prevents initial C2 resolution. The final C2 observed was 82.25.63.156:9000.

WinHTTP session parameters:

  • User-Agent: SystemInfo Client/1.0
  • All timeouts set to 60 seconds (DNS resolve, connect, send, receive)
  • Scheme: HTTPS to steamcommunity.com, then HTTP/HTTPS to resolved C2

6. Stage 5 — Browser Credential Theft & ABE Bypass

VoidStealer targets Chrome and Edge-based browsers to extract cookies, saved credentials, autofill data, credit cards, browsing history, bookmarks, and downloads. To bypass the Application-Bound Encryption (ABE) protection introduced in modern Chromium builds, it uses a hardware breakpoint-based technique to extract the v20_master_key directly from browser memory.

ABE Bypass Technique

①
Create a new Chrome or Edge process in a suspended state using CreateProcess(CREATE_SUSPENDED).
②
Search the browser process memory for the string OSCrypt.AppBoundProvider.Decrypt.ResultCode to locate the target address within the .text section.
③
Obtain the target thread handle and set a hardware breakpoint (via SetThreadContext / debug register Dr0) on the identified address.
④
Resume the browser process. When it reaches the breakpointed address, execution is intercepted via the debug exception handler.
⑤
The malware reads the v20_master_key directly from the browser's register state / memory at the point of interception. This key is then used to decrypt all ABE-protected browser data.

Browsers targeted (recovered from decrypted strings):

Google Chrome Microsoft Edge Brave Browser Opera Opera GX Mozilla Firefox Discord Telegram Steam FileZilla

SQL queries used for browser data extraction (recovered from RC4-decrypted strings):

SELECT host_key, name, encrypted_value, path, expires_utc, is_secure, is_httponly FROM cookies SELECT origin_url, username_value, password_value, date_created FROM logins SELECT name, value FROM autofill SELECT name_on_card, expiration_month, expiration_year, card_number_encrypted FROM credit_cards SELECT url, title, visit_count, last_visit_time FROM urls ORDER BY last_visit_time DESC LIMIT 1000 SELECT target_path, tab_url, total_bytes FROM downloads SELECT short_name, keyword, url FROM keywords

7. String Obfuscation — Base64 + RC4

VoidStealer hides all operational strings from static analysis using a two-stage decryption routine. Each string has its own unique hardcoded 32-byte RC4 key, making bulk decryption require per-entry key extraction.

Decryption algorithm: plaintext = RC4(key, Base64Decode(ciphertext))
The malware first decodes the Base64-encoded ciphertext, then uses the corresponding 32-byte key to initialise the RC4 KSA and decrypt the result. Decrypted strings include browser artifact names, file paths, API endpoints, HTTP headers, JSON field names, and Native API names used for injection primitives.
