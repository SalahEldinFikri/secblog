MALWARE ANALYSIS KERNEL ROOTKIT WINDOWS APT OPERATION TUNNELSNAKE

Moriya: Kernel-Mode Rootkit Analysis — Operation TunnelSnake

📅 2025 ⏱ 14 MIN READ ✍ SalahEldin Kamil CRITICAL
Technical analysis of Moriya — a sophisticated kernel-mode rootkit first documented as part of Operation TunnelSnake (2021). The malware establishes persistence as an svchost.exe service, drops a kernel driver (MoriyaStreamWatchmen.sys), bypasses Driver Signature Enforcement via a hijacked VBoxDrv.sys, and maintains a passive TCP reverse shell over pseudo-random ports 50000–50099. Commands flow through named pipes to a spawned cmd.exe, while a second thread forcibly kills taskhostw.exe and taskhost.exe.

1. Architecture & Execution Overview

Moriya is implemented as a Windows DLL with three exported functions. The DllMain entry point performs no meaningful action — all malicious functionality is split between Install (persistence setup) and ServiceMain (runtime operation).

EXPORT 1
DllMain
No-op — does nothing on attach. All logic deferred to the two explicit exports.
EXPORT 2
Install
One-time persistence: creates NsmSvc service, sets registry values, injects into netsvcs group.
EXPORT 3
ServiceMain
Runtime: spawns two threads — Thread 1 drops the kernel driver and runs the C2 channel; Thread 2 kills host processes.
KERNEL
MoriyaStreamWatchmen.sys
Kernel-mode rootkit component — network packet interception via WFP callout driver, device + named pipe for IPC.
Figure 1 — DllMain performs no action; all functionality resides in Install and ServiceMain exports

2. Persistence — netsvcs Service Injection

The Install export establishes long-term persistence by registering Moriya as a Windows service that loads its DLL through the legitimate svchost.exe -k netsvcs hosting process.

①
SCM connection & service creation — Opens the Service Control Manager and creates a new service with the following configuration:
FIELD VALUE NOTE
Service Name NsmSvc Short name — registered in SCM and registry
Display Name Network Services Manager Blends with legitimate service names
Access Rights SERVICE_ALL_ACCESS Full control granted to the service
Service Type SERVICE_WIN32_OWN_PROCESS Runs in its own svchost instance
Start Type SERVICE_AUTO_START Automatically starts on every boot
Binary Path C:\Windows\System32\svchost.exe -k netsvcs Legitimate host — masks malicious DLL
②
ServiceDll & ServiceMain registry values — Opens HKLM\SYSTEM\CurrentControlSet\Services\NsmSvc\Parameters and writes two values that instruct svchost how to load Moriya:
HKLM\SYSTEM\CurrentControlSet\Services\NsmSvc\Parameters ServiceDll = <path to Moriya DLL> ServiceMain = "ServiceMain"
③
netsvcs group injection — Opens HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Svchost, reads the existing REG_MULTI_SZ value for netsvcs, appends NsmSvc to the list, and writes it back. This causes Windows to recognise NsmSvc as a member of the netsvcs service group and load it inside svchost.exe -k netsvcs on the next boot.
Detection: Sysmon EID 4697 / Windows Security EID 7045 on NsmSvc installation. Alert on writes to HKLM\...\Svchost\netsvcs from non-Windows-Update processes — appending to this list is a classic svchost hijacking pattern. The service binary path pointing to svchost.exe -k netsvcs with a ServiceDll pointing to a non-Microsoft DLL is the key anomaly.
Figure 2 — Install function: SCM service creation → ServiceDll registry values → netsvcs group injection

3. ServiceMain — Two-Thread Architecture

When Windows starts the NsmSvc service, it calls ServiceMain. The function updates the service status with the SCM, then immediately spawns two concurrent threads with distinct responsibilities.

THREAD 1 — DRIVER & C2
Sleeps 60 seconds, then drops MoriyaStreamWatchmen.sys from embedded resources. Bypasses DSE via VBoxDrv. Establishes TCP connection to C2. Processes commands via named pipe to cmd.exe.
THREAD 2 — PROCESS KILLER
Enumerates running processes. Forcibly terminates taskhostw.exe and taskhost.exe. Likely a defence evasion mechanism targeting task scheduling host processes.
Figure 3 — ServiceMain: SCM status update then CreateThread × 2 — driver+C2 thread and process-killer thread

4. Thread 1 — Kernel Driver Drop & DSE Bypass

After the initial 60-second sleep, Thread 1 performs the kernel-level setup in sequence:

①
Sleep(60 000 ms) — A 60-second delay before any kernel activity begins. Sandbox environments with short execution windows will not observe the driver drop or C2 activity.
②
MoriyaStreamWatchmen.sys drop — Loads the kernel driver from an embedded resource and writes it to C:\Windows\System32\drivers\MoriyaStreamWatchmen.sys. Creates and starts a service for it under the name MoriyaStreamWatchmen.
③
DSE bypass via VBoxDrv — Locates a vulnerable VirtualBox driver (VBoxDrv.sys) on the system. Renames the original to VBoxDrv.backup, then drops a second embedded file in its place. Creates and starts a new VBoxDrv service from this file. The VirtualBox driver is known to be abusable for disabling Driver Signature Enforcement (DSE) — a common BYOVD (Bring Your Own Vulnerable Driver) technique.
④
IOCTL communication — Issues IOCTL 0x222004 to the MoriyaStreamWatchmen device to configure the driver's network monitoring behaviour.
⑤
Driver self-deletion — Deletes MoriyaStreamWatchmen.sys from disk after loading the driver into the kernel. The driver remains active in memory; the on-disk artefact is removed to hinder forensic analysis.
BYOVD / DSE bypass: Using VBoxDrv.sys to disable Driver Signature Enforcement is a known technique (CVE-2008-3431 and variants). The malware exploits the kernel-level access granted by the vulnerable driver to load its own unsigned MoriyaStreamWatchmen.sys without triggering DSE checks. Detection: alert on VBoxDrv service creation outside VirtualBox installation paths, especially when accompanied by a backup file creation.
Figure 4 — Thread 1: MoriyaStreamWatchmen.sys drop to System32\drivers, VBoxDrv.sys manipulation for DSE bypass, service creation

5. TCP Reverse Shell & C2 Channel

After the kernel driver is established, Thread 1 sets up the command-and-control communication channel via a direct TCP reverse shell.

socket()AF_INET, SOCK_STREAM
bind()port 50000–50099 (random)
DnsQuery_Aresolve C2 hostname
WSAConnect()192.168.152.1:80
Redirect stdiostdin/stdout/stderr → socket
CreateProcesscmd.exe (interactive shell)
  • Socket creation — Creates an IPv4 TCP socket and binds to a pseudo-random local port in the 50000–50099 range.
  • C2 resolution — When a hostname is supplied via the connect command, the malware resolves it using DnsQuery_A. The observed hardcoded endpoint is 192.168.152.1:80.
  • WSAConnect — Establishes the TCP connection to the resolved C2 endpoint.
  • stdio redirect — Redirects the spawned process's standard input, output, and error streams directly to the C2 socket via STARTUPINFO handle inheritance.
  • Interactive shell — Launches C:\Windows\System32\cmd.exe with stdio bound to the socket, giving the operator a fully interactive remote command shell.
Detection: cmd.exe spawned by svchost.exe with inherited socket handles is anomalous — Sysmon EID 1 with ParentImage = svchost.exe and CommandLine = cmd.exe and no console window. Alert on outbound connections from svchost.exe on port 80 to non-Microsoft IP addresses. The local port range 50000–50099 is also a network-layer signature.
Figure 5 — TCP reverse shell: random bind port 50000–50099, WSAConnect to 192.168.152.1:80, cmd.exe stdio redirected to socket

6. Named Pipe Command Processing

Beyond the direct TCP shell, Moriya uses the MoriyaStreamWatchmen driver as a communication bridge via named pipes and a device object.

①
Device creation — The kernel driver creates a device object (\\Device\\MoriyaStreamWatchmen) and a symbolic link (\\DosDevices\\MoriyaStreamWatchmen). The user-mode component opens this device for IPC.
②
Pipe creation — CreatePipe establishes the read/write pipe pair used to relay commands to and output from the cmd.exe shell process.
③
Command deobfuscation — Commands received through the Moriya communication stream are deobfuscated before being passed to cmd.exe via the pipe write handle.
④
Output polling — PeekNamedPipe + ReadFile poll the pipe read handle for shell output. The malware waits for the > prompt character to appear, using it as the signal that command processing is complete.
⑤
Output obfuscation & relay — The collected shell output is processed through the obfuscation routine and transmitted back through the Moriya communication channel to the operator.
Figure 6 — Named pipe IPC: CreatePipe, deobfuscate command → WriteFile to cmd.exe, PeekNamedPipe/ReadFile poll for > prompt, obfuscate output, relay to C2

7. Thread 2 — Process Termination

The second thread runs concurrently with Thread 1 and focuses solely on locating and killing specific host processes.

  • Calls CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS) and iterates with Process32FirstW / Process32NextW.
  • Targets taskhostw.exe and taskhost.exe — the Windows Task Host processes responsible for running scheduled tasks and DLL-based services.
  • Opens each match with OpenProcess(PROCESS_TERMINATE) and calls TerminateProcess.
Likely intent: Killing taskhostw.exe / taskhost.exe prevents scheduled tasks — including security product maintenance tasks, update checks, and log rotation — from running during the infection. It may also be used to disrupt task-based detection or remediation mechanisms. Impact on service disruption is not fully confirmed from the analysed code alone.
Figure 7 — Thread 2: CreateToolhelp32Snapshot → Process32FirstW/NextW → TerminateProcess on taskhostw.exe and taskhost.exe

10. YARA Detection Rule

The rule targets both the user-mode DLL and the kernel driver by matching on unique Moriya-specific string constants present across all observed components. Any 5 of the 10 strings is sufficient for a high-confidence match.

rule Moriya { meta: description = "Detects Moriya kernel-mode rootkit — Operation TunnelSnake" author = "SalahEldin Kamil (Mr_MaTriX)" strings: $m1 = "MoriyaStreamWatchmen" ascii wide $m2 = "MoriyaServiceX64.dll" ascii wide $m3 = "Moriya" ascii wide $m4 = "Moriya start" ascii wide $m5 = "Moriya Callout" ascii wide $m6 = "Moriya Filter" ascii wide $m7 = "\\Device\\MoriyaStreamWatchmen" ascii wide $m8 = "\\DosDevices\\MoriyaStreamWatchmen" ascii wide $m9 = "Moriya : Waiting..." ascii wide $m10 = "Moriya : NotifyFunction" ascii wide condition: uint16(0) == 0x5A4D // MZ header and filesize < 5MB and 5 of ($m*) }
