Vortex: Go-Based Infostealer with Telegram C2 and AV Evasion

📅 2025 ⏱ 12 MIN READ ✍ SalahEldin Kamil HIGH
Analysis of Vortex — a Windows-focused infostealer written in Go that operates as both a data exfiltration tool and a flexible backdoor. The implant fingerprints the victim, aggressively disables defences via registry manipulation and PowerShell, then collects browser credentials, crypto wallets, VPN configs, messenger sessions, and more — exfiltrating everything through an AES-encrypted Telegram bot C2 channel.

1. Execution Flow Overview

Vortex executes in a strict sequential order before beginning data collection. Each stage is a dependency for the next — defences must be down before stealing, and persistence is set last.

STAGE 1
Dump Directory
Create collection dir named 7900020458
STAGE 2
IP Fingerprinting
HTTP GET to ipapi.co/json — public IP, country, ISP, timezone
STAGE 3

STAGE 4

STAGE 6

STAGE 8
C2 Exfiltration
AES+Base64 encrypted upload via Telegram Bot API
STAGE 9
Persistence
Self-copy + Run registry key

2. Victim Fingerprinting

2.1 Public IP & Geolocation

The malware performs an HTTP GET request to https://ipapi.co/json using net_http_NewRequestWithContext. The request header includes a hardcoded Chrome-mimicking User-Agent:

Mozilla/5.0 (Windows NT 10.0) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/99.0.7113.93 Safari/537.36

The JSON response is unmarshalled into the opsysinfo.IpInfo structure, capturing: public IP address, country, region, city, ISP/org, timezone, and currency. This data is included in the victim profile sent to the Telegram C2.

Figure 2 — IP fingerprinting: net_http_NewRequestWithContext GET to ipapi.co/json, Chrome UA header, JSON unmarshal into opsysinfo.IpInfo

2.2 System Information

After IP geolocation, Vortex collects local hardware and user context:

  • Operating system name and version
  • CPU model and core count
  • Total installed RAM
  • Current logged-in username and hostname
  • System locale and language
Figure 3 — Host fingerprinting: OS, CPU, RAM, and logged-in user collection

3. Log File Setup

Before disabling defences, Vortex sets up its internal logging infrastructure. The procedure is:

①
Kernel32.dll load — Loads kernel32.dll dynamically for subsequent API calls.
②
CrashHandler.log encryption — Encrypts the log file name CrashHandler.log and appends it to a string prefixed with ERB1-7C using Base64 encoding. The prefix acts as a simple obfuscation marker.
③
Log file creation — Constructs the full path inside the dump directory (7900020458) and creates the CrashHandler.log file there.
④
Log redirect — Redirects all subsequent internal log output to the newly created file, making all malware activity traceable in a local log that is later exfiltrated.
Figure 4 — Log file setup: Kernel32 load, ERB1-7C Base64 prefix, CrashHandler.log creation in dump dir, log redirect

4. Defence Disabling

Vortex performs the most aggressive defence-disabling sequence of any sample in this series — hitting UAC, Windows Defender, driver services, and the C: drive exclusion in sequence before touching any victim data.

4.1 UAC Disable

Opens HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System and sets EnableLUA = 0, disabling User Account Control entirely. Takes effect on next logon.

4.2 Windows Defender Registry Tampering

Opens HKLM\SOFTWARE\Microsoft\Windows Defender and sets multiple values to disable real-time protection, cloud-delivered protection, behaviour monitoring, and IOAV protection:

Figure 5 — Defender registry tampering: DisableAntiSpyware, DisableRealtimeMonitoring, DisableBehaviorMonitoring, DisableIOAVProtection values set

4.3 Driver Service Disabling

Iterates a hardcoded array of driver/service names and opens each under HKLM\SYSTEM\CurrentControlSet\Services\<name>, setting Start = 4 (disabled) to prevent the service from loading on the next boot. Targets include security-related kernel drivers.

Figure 6 — Driver service disabling: iterates service name array, sets Start=4 (disabled) under CurrentControlSet\Services for each entry

4.4 PowerShell AV Manipulation

Iterates a list of Set-MpPreference parameters and disables each one, then modifies Defender's threat response behaviour, sample submission, and MAPS reporting settings:

Figure 7 — PowerShell AV manipulation: Set-MpPreference loop disabling all protection features, sample submission, and MAPS reporting

4.5 C:\ Drive Exclusion

Adds the entire C:\ drive and all processes launching from it to Windows Defender's exclusion list — effectively making Defender blind to any file or process on the system drive:

Add-MpPreference -ExclusionPath "C:\" -Force -ErrorAction SilentlyContinue Add-MpPreference -ExclusionProcess "C:\*" -Force -ErrorAction SilentlyContinue
Detection: Sysmon EID 1 — powershell.exe with Set-MpPreference and Add-MpPreference arguments spawned from a non-administrative shell is a high-fidelity alert. Alert on EnableLUA=0 registry writes from non-installer processes. Windows Security EID 5001 (Defender disabled).
Figure 8 — C:\ exclusion: Add-MpPreference ExclusionPath C:\ and ExclusionProcess C:\* — makes Defender blind to all files and processes on the system drive

5. Process Termination

After disabling Defender, Vortex enumerates all running processes, builds a list of process names and PIDs, identifies security-related targets, terminates them, then sleeps for 2 seconds before continuing.

Pattern: The 2-second sleep after process termination is a synchronisation delay — it gives the OS time to fully clean up terminated process handles before the malware begins accessing locked files (browser databases, etc.) that the killed processes may have held open.
Figure 9 — Process enumeration: builds name/PID list, identifies targets, TerminateProcess, Sleep(2000)

7. Telegram Bot C2

All C2 communication runs through the Telegram Bot API. The implant decrypts the operator's bot token at runtime (Base64+AES), constructs the Bot API URL, and sends HTTP POST requests with a Content-Type: application/json header and a hardcoded Chrome-like User-Agent. JSON responses are unmarshalled into telehandler_msgResponse.

The operator controls the implant through the following Telegram bot commands:

COMMANDDESCRIPTION
/check <ZOMBIE_ID>Check if a specific victim host is online
/check_allList all connected victims and their online status
/screenshot <ZOMBIE_ID>Capture and return a desktop screenshot from the victim
/get_data <ZOMBIE_ID> <TYPE> <PATH>Collect images or documents from a specific path on the victim
/drop <ZOMBIE_ID> <URL> <NAME> <PATH>Download and execute a secondary payload on the victim
/upgrade <ZOMBIE_ID> <URL> <NAME>Replace the running implant with an updated version
/disable_upload <ZOMBIE_ID>Stop data upload for a specific victim
/enable_upload <ZOMBIE_ID>Resume data upload for a specific victim

9. Persistence

After data collection and exfiltration, Vortex establishes persistence as the final step — ensuring it survives reboots and user logoffs.

①
Self-copy — Copies its own executable to a different location on disk (typically a system or user-accessible directory) under a disguised name.
②
Run key write — Opens Software\Microsoft\Windows\CurrentVersion\Run and writes a new value pointing to the copied executable. The malware will launch automatically on every user logon.
Detection: Sysmon EID 13 (RegistryValueSet) on HKCU\Software\Microsoft\Windows\CurrentVersion\Run from a Go binary (check image entropy and lack of version info). The Run key write happens after data collection — if defences are re-enabled before reboot, the persistence key may be the only remaining artefact.

12. YARA Detection Rule

The rule targets Go-compiled Vortex binaries by matching on package path strings embedded by the Go compiler — these are present in any build regardless of obfuscation applied at the binary level. Any 5 of the 10 strings produces a high-confidence match.

rule Vortex { meta: description = "Detects Vortex Stealer — Go-based infostealer with Telegram C2" author = "SalahEldin Kamil (Mr_MaTriX)" strings: $m1 = "vortex" ascii wide $m2 = "vortex/messenger.DiscordDataDump" ascii wide $m3 = "vortex/hutil.mergeBrowserData" ascii wide $m4 = "vortex/hutil.archiveDataFiles" ascii wide $m5 = "vortex/hutil.CompressDataFiles" ascii wide $m6 = "vortex/hutil.archiveFiles" ascii wide $m7 = "vortex/hutil.ZipFolder" ascii wide $m8 = "vortex/antiav.DisableUAC" ascii wide $m9 = "vortex/antiav.disableWinDefendRegs" ascii wide $m10 = "vortex/browser.RecursiveChromiumBrowserDump" ascii wide condition: uint16(0) == 0x5A4D // MZ header and filesize < 10MB and 5 of them }
